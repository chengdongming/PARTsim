# F2利用率边界增量实验

这轮只为CPU利用率和能量利用率曲线补充两端的数据，保留已完成的F2正式实验。
不修改RTA、SEQ、原生成器、原协议或原结果文件。

## 上传一个脚本启动

下载仓库中的 `tools/ab_rta_f2_edges.py`，上传到原AutoDL服务器的 `/root/autodl-tmp/`。
原实验目录 `/root/autodl-tmp/ab_rta_f2` 及其中的代码、venv和完整结果需要保留。
原批次应已经显示COMPLETE，使用同一实例、相同资源配额和依赖。

```bash
cd /root/autodl-tmp
python ab_rta_f2_edges.py start
```

无需拉取新代码或安装依赖。启动器会调用原venv，在tmux后台运行补测，默认最多28路。
原代码源文件摘要必须为
`f0fb5bdc6f9f847d8fa70eeb39be77a6ec4cadbebdfee2850ba52dc1621c1014`。
原依赖为PyYAML 6.0.3、NumPy 2.3.5、Matplotlib 3.10.8。
当前硬件和依赖与原主实验不一致时，脚本会停止，而不会把不同测量条件合并为同一批结果。

```bash
python ab_rta_f2_edges.py status
python ab_rta_f2_edges.py logs
python ab_rta_f2_edges.py resume
```

status直接给出完成数量、总请求数、百分比和阶段。分析达到100%后还要完成独立核验与作图，
以state显示COMPLETE为准。resume跳过已经保存的请求；同一目录的脚本、输入和并发配置被冻结。
断线不影响后台运行；关机后需要resume。错误和不通过的核验不会被忽略。

如原目录不是默认位置，在首次及后续命令中使用同样的路径：

```bash
python ab_rta_f2_edges.py start --base-root /原实验目录 --root /新的独立补测目录
```

## 为什么不把0.05替换为0

原任务模型要求非空任务集、整数工作量C至少为1、单位执行能耗严格大于0。
所以归一化CPU利用率和能量利用率都严格大于0。0不是这个模型内可生成的合法输入。
脚本不将0.05改标为0，也不在0处填入猜测的0%或100%认证率。

利用率横轴统一显示0至1，0仅作为刻度；最左侧新增真实测量点为0.05。
上端1.00是真实测量的目标参数，不是将0.95改标成1。
CPU整数化仍沿用原总利用率误差容限0.01；在目标CPU利用率1.00处，
若整数化后实际CPU利用率大于1，则在分析前丢弃该输入，按固定候选索引i+100k重采样。
该规则只依据输入是否合法，不使用任何RTA结果，不修改C或截止期来隐藏超界。
所有接受与舍弃的生成记录都保存；本地完整生成检查共舍弃222个越界候选。
